Open Source Quality

How I discovered that some open source libraries have an incredibly high standard of quality.

 Posted on February 20, 2026  |  Jherek Healy

Recently, I have made a small contribution to an existing open-source project called Apache Commons RNG. While it is a very basic contribution: Java implementations of Philox4x32 and Philox4x64 pseudo random number generators from John Salmon. Those are the popular standard in many libraries (Pytorch, CUDA, Numpy), because of their good properties, simplicity, and ease of parallelization.

The ease of parallelization is inherent to counter-based random number generators, which allow jumping at any location in the stream at essentially no cost. This means we can either slice the sequence in any way we want, or create independent substreams using very long jumps. While the ability to create independent substreams is relatively common in modern random number generators, arbitrary jumps are not and can be particularly nice at making sure we use a given sequence of numbers regardless of the number of cores/threads: we just need to define a slicing strategy for N cores/threads (Note: this strategy is only applicable if we don’t use any acceptance/rejection based algorithm as in quasi Monte-Carlo simulations), see also this post.

I was not able to find an official Java implementation of those in any popular library (actually even in any obscure library), which shows the aging status of the Java programming language. This is why I decided to provide some, and adding those to a project from the Apache foundation was a natural best fit, considering how popular these libraries are in the Java community.

I was extremely surprised at the quality of the open source project. The checkstyle settings are very strict towards indentation, code comments. The project also makes use of PMD to ensure high quality of code, and Jacoco to make sure the coverage is over 99%. Yes, you’ve read that right, the standard for coverage is a minimum of 99%. I have never seen such a high quality in corporate code in my life. They also rely on JMH for performance testing, and have an extensive suite of tests to verify the quality of random number generators.

Furthermore, the maintainers of Apache Commons RNG made good remarks on simplifying my contribution, and cared about some concerns I had about providing arbitrary jump-ahead. I don’t know where they find all this time.

Now not everything is rosy. The project requires compatibility with Java 8, first released in 2014… So you can’t use newer features or APIs. In theory, it could be possible, for example through multi-release JAR files, which are quite simple to put in place. But those don’t play well with Jacoco, and understandably so since test coverage may then be dependent on the JVM.
