Burley Scrambling Beyond the Fourth Dimension

 Posted on August 24, 2026  |  Jherek Healy

Brent Burley, of Walt Disney Animation Studios, presented an excellent hash-based algorithm for implementing full Owen (nested uniform) scrambling of the Sobol sequence: Practical Hash-based Owen Scrambling, JCGT vol. 9, no. 4, 2020 [1].

Before that paper, the standard reference for scrambling low-discrepancy sequences was ACM Algorithm 823 by Hong and Hickernell [2], which is slower and only approximates Owen’s nested uniform scrambling. To keep memory and computation bounded, it uses Matoušek’s nested-linear approximation (affine permutations of the form A · x + C mod b) rather than a fully independent random permutation at every node of the digit tree [3].

Burley’s contribution was to show that a chain of multiply-XOR operations—the Laine–Karras hash, applied to a bit-reversed input—reproduces an exact nested uniform (Owen) permutation in base two, cheaply and without any precomputed table.

Why four dimensions?

Because Burley’s use case is path-traced rendering, the paper and its reference code are built natively around four dimensions at a time: two for the pixel position and two for the lens (depth-of-field) sample.

The paper is explicit that this is a deliberate choice. With the sample counts typical in graphics—a few thousand samples per pixel at most—there is little benefit to a genuinely high-dimensional Sobol construction, since the t-value of the Sobol sequence grows quickly with dimension:

  • t = 3 at 4D
  • t = 5 at 5D
  • t = 8–23 at 6–10D

This pushes the sample count needed to see the improved convergence rate toward \(2^{t \cdot s}\) [1, Section 2.3], where s is the dimension.

For 4D, this corresponds to 4,196 samples, but for 5D it is over 33 million samples.

So instead of extending the Sobol matrices themselves to more dimensions, the paper proposes padding: reuse the same low-dimensional (here, 4D) Sobol construction for every group of dimensions, and decorrelate each group from the others with a different seed.

The core algorithm

Here is the code central to Burley’s algorithm:

inline void shuffled_scrambled_sobol4d(uint32_t index, uint32_t seed,
                                       uint32_t X[4])
{
  index = nested_uniform_scramble_base2(index, seed);
  sobol4d(index, X);
  for (int i = 0; i < 4; i++) {
    X[i] = nested_uniform_scramble_base2(X[i], hash_combine(seed, i));
  }
}

There are three steps:

  1. Shuffle the sample index. nested_uniform_scramble_base2(index, seed) applies the Laine–Karras permutation, bit-reversed, to the index rather than to a sample value. This is a nested-uniform shuffle of the sample order, decorrelating which physical index maps to which point in the sequence. It uses one arbitrary seed.

  2. Generate the point. Look up (or compute) the 4D Sobol point at the shuffled index.

  3. Scramble each coordinate. Apply nested_uniform_scramble_base2 again, this time to each of the four output values, using a separate seed for each coordinate derived from hash_combine(seed, i).

Padding beyond four dimensions

For dimensions beyond four, the paper’s recipe is simple [1, Section 4]:

“one merely needs to supply a different seed to each group of four dimensions”

In other words, for D dimensions, draw (D/4) independent random integers and use one seed for each group of four dimensions.

This is essentially the approach taken in QuantLib’s implementation of Burley’s algorithm,

On the use a high dimensional direction vector table

QuantLib Burley2020SobolRsg, contributed by Peter Caspers [4, 5], generates its scrambling seeds from a Mersenne Twister at initialization time. The seeds are then fixed for the lifetime of the generator and used to key the Laine–Karras/nested-scramble step for the index shuffle and for each dimension. But more importantly, it does not use padding but uses direction vectors in high dimension (e.g. from Joe and Kuo).

A slightly different approach, briefly described on the Chase the Devil blog [6], is to draw D + 1 independent random integers up front from an ordinary, well-tested PRNG: one seed to shuffle the sample index, and one seed per dimension to scramble it.

This has two advantages over the hash-chain approach:

  • Robustness. You’re relying on the statistical quality of a well-studied general-purpose PRNG (Mersenne Twister, Philox, etc.) to produce D + 1 independent seeds.
  • No repeated hashing per sample. With independent precomputed seeds, each dimension’s seed is a stored constant, looked up once per generator, rather than recomputed via hash_combine on every call.

That said, this is a minor cost either way. Burley notes that the Laine–Karras/Owen step itself already dominates, and that jumping to arbitrary sample indices, rather than incrementing them, is the real performance bottleneck.

The main drawback of the high dimensional direction vector approach is to (of course) require the same good old 21,201-dimensional direction-vector table from Joe and Kuo. In contrast, the 4-by-4 approach only requires the tiny table for four dimensions and can go beyond 21,201 dimensions.

Overall, Burley’s 4-by-4 scrambling approach is remarkably self-contained and small.

Update 2026/08/25 Padding is fundamentally worse than the seed per dimension, see my next post.

Permuting over \(2^{32}\) or over \(2^L\)?

When generating \(N = 2^L\) samples, should the shuffle be defined as a permutation of the full 32-bit index range \([0, 2^{32})\), or restricted to the \([0, 2^L)\) range actually being sampled?

There is no theoretical gain in restricting the permutation to \(2^L\), and there is an important practical issue: the permutation would then become dependent on the number of draws \(2^L\).

That is unacceptable. The first 1,024 numbers of a sequence of 2,048 samples should correspond to the sequence of 1,024 samples—not to a different permutation produced specifically for the shorter sequence.

The shuffle should therefore be defined independently of the number of samples being drawn.
